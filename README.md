# Telegram-бот напоминаний с еженедельным режимом

Бот помогает руководителю ставить задачи сотрудникам и следить за выполнением.
В этой версии добавлен **еженедельный режим**: задача повторяется в выбранный
день недели, а внутри дня — несколько отправок с заданным интервалом.

## Новый режим в двух словах

Пример из задачи:

- день — **понедельник**;
- первая отправка — **19:00**;
- интервал — **30 минут**;
- количество отправок — **5**.

Сообщения придут в 19:00, 19:30, 20:00, 20:30 и 21:00. На следующей неделе
в понедельник в 19:00 схема начнётся заново — независимо от того, нажал
сотрудник «Сделано» или нет.

Кнопка **«✅ Сделано»** закрывает только **текущую серию**. Следующая серия
запустится автоматически в ближайший выбранный день. Если сотрудник не
подтвердил выполнение, серия всё равно повторится на следующей неделе.

## Как создать еженедельную задачу

1. `➕ Новое напоминание` → выбрать сотрудника.
2. Ввести текст задачи.
3. Выбрать часовой пояс: Санкт-Петербург или Норильск.
4. Выбрать режим **«🔄 Каждую неделю»**.
5. Выбрать день недели кнопкой.
6. Ввести время первой отправки, например `19:00` (есть быстрые кнопки).
7. Выбрать интервал между отправками (1 раз, 15/30 минут, 1/2 часа или свой).
8. Указать количество отправок в этот день.
9. Проверить карточку и нажать **«✅ Подтвердить»**.

Бот не даст создать серию, которая выходит за пределы выбранного дня
(после 23:59): в этом случае он покажет максимально допустимое количество
отправок.

## Статусы

| Статус | Что означает |
|---|---|
| `active` | Серия идёт, следующая отправка запланирована |
| `done` | Текущая серия подтверждена кнопкой «Сделано» |
| `exhausted` | Все отправки серии сделаны, подтверждения нет |
| `cancelled` | Задачу отменил руководитель |
| `failed` | Не удалось доставить сообщение (например, сотрудник не нажал Start) |

Для еженедельной задачи `done` и `exhausted` — временные состояния: в
следующий выбранный день серия автоматически снова станет `active`.
Отмена (`cancelled`) и ошибка доставки (`failed`) останавливают задачу совсем.

## Что видит руководитель

- **📋 Активные** — текущие разовые задачи и еженедельные серии, включая
  закрытые до следующей недели; для каждой показано, когда будет следующая
  отправка или следующая серия.
- **🗂 История** — последние 15 завершённых серий: выполнена, отменена,
  отправки закончились, ошибка доставки. Для еженедельных задач каждая неделя
  хранится отдельной строкой.
- Уведомления в личку: сотрудник нажал «Сделано», серия закончилась без
  подтверждения, следующая серия начнётся в таком-то числе, ошибка доставки.

## Что видит сотрудник

- Напоминание с кнопками **«✅ Сделано»** и **«⏰ Отложить на N мин»**.
- После «Сделано» можно приложить отчёт: фото, файл или текст — бот перешлёт
  его руководителю.
- **📌 Мои задачи** — активные и незавершённые серии.

Кнопки в старых сообщениях содержат номер серии. Поэтому нажатие «Сделано»
на прошлой неделе не закроет новую серию — бот ответит, что серия уже
завершена.

## Установка и запуск

Требуется Python 3.11+.

```powershell
pip install -r requirements.txt
$env:BOT_TOKEN = "123456789:AA..."
$env:ADMIN_IDS = "111111111,222222222"
python bot.py
```

Переменные окружения:

| Переменная | Обязательна | По умолчанию | Назначение |
|---|---|---|---|
| `BOT_TOKEN` | да | — | Токен от @BotFather |
| `ADMIN_IDS` | да | — | ID руководителей через запятую |
| `SNOOZE_MIN` | нет | `30` | На сколько минут откладывается напоминание |
| `DB_PATH` | нет | `data/reminders.db` | Путь к SQLite-базе |
| `SCHEDULER_TICK` | нет | `20` | Период проверки расписания, секунды |
| `WEEKLY_LATE_GRACE_H` | нет | `6` | Сколько часов опоздания серии ещё считается допустимым |

На Windows обязательно установите `tzdata` (он уже указан в
`requirements.txt`), иначе `ZoneInfo("Europe/Moscow")` не найдёт часовой пояс.

## Обновление старой базы

Миграция выполняется автоматически при запуске: в таблицу `reminders`
добавляются поля `mode`, `weekday`, `day_minute`, `series_no`, `series_start`,
`reopen_ts`, `created_ts`, создаётся таблица `series_history`. Старые
напоминания и их история не удаляются.

## Поведение в пограничных случаях

- **Бот был выключен.** Если серия опоздала не больше чем на
  `WEEKLY_LATE_GRACE_H` часов, она стартует сразу. Если больше — пропущенная
  неделя не проигрывается, следующая серия ставится на ближайший выбранный
  день.
- **Сотрудник откладывает.** «Отложить» сдвигает только ближайшую отправку
  текущей серии; расписание следующей недели не меняется.
- **Серия не успела завершиться до следующей недели** (например, из-за
  откладываний). Планировщик закрывает её как `exhausted` и запускает новую
  серию по расписанию.
- **Ошибка доставки.** Серия останавливается со статусом `failed`,
  руководитель получает уведомление. Это защищает от бесконечных ошибок,
  если сотрудник заблокировал бота.
- **Разовый режим** работает как раньше: после последней отправки задача
  получает `exhausted` и больше не повторяется.

## Проверки

Тесты не ходят в Telegram и используют временную SQLite-базу:

```powershell
python tests/test_weekly.py
python tests/test_migration.py
```

Первый проверяет полный недельный цикл (5 отправок → `exhausted` → новая
серия), закрытие только текущей серии кнопкой «Сделано», защиту от кнопок
прошлой серии, отсутствие регрессии у разового режима, расчёт ближайшего дня
недели и вместимости серии в сутки. Второй — обновление базы старого формата
без потери задач и истории.
